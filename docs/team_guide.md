# Внутренний регламент и руководство команды проекта

Данный документ описывает текущее состояние инфраструктуры проекта, зоны ответственности участников команды и регламент совместной работы в Git и GitHub.

---

## 1. Что уже подготовлено и настроено

Базовая инфраструктура проекта развёрнута и готова к параллельной работе:

1. **Структура репозитория:**
   Создан каркас каталогов по требованиям ТЗ:
   - `docs/` — аналитика, карты данных, матрица доступа, диаграммы (`analysis/`, `diagrams/`)[cite: 1];
   - `sql/` — DDL-миграции, тестовые данные, аналитические запросы, серверная логика (PL/pgSQL), скрипты прав доступа (DCL)[cite: 1];
   - `python/` — клиентские скрипты подключения, пакетной загрузки, валидации данных и паттернов СУБД[cite: 1].
2. **Изоляция данных и окружения (`.gitignore`):**
   Настроена фильтрация: виртуальное окружение `venv/`, локальные дампы, `.env`, служебные файлы IDE и тяжёлые файлы датасетов (`*.csv`, `*.xlsx`, `*.parquet`, папка `data/`) изолированы и не попадают в удалённый репозиторий.
3. **Защита главной ветки (`main`):**
   Ветка `main` заблокирована настройками безопасности:
   - Прямой пуш (`git push origin main`) запрещён.
   - Все изменения вносятся исключительно через механизм Pull Request после рецензирования.
   - Обращение к ветке `main` предусмотрено только на финальном этапе перед итоговой сдачей проекта. Локальное переключение на `main` и внесение правок в процессе текущей разработки исключены.
4. **Интеграционная ветка (`develop`):**
   Создана и назначена основной рабочей веткой по умолчанию. Все функциональные ветки формируются от `develop` и объединяются с ней:
   - Прямой пуш (`git push origin develop`) также запрещён.
   - Все изменения вносятся исключительно через Pull Request (PR) после ревью.
5. **Проектная доска (GitHub Projects):**
   Настроена канбан-доска с ролевой разметкой (Data Analyst, DBA, Developer) для распределения и контроля задач. Созданы тикеты проекта.

## 2. Зоны ответственности участников команды

Каждый участник ведёт ключевое направление по ТЗ, обеспечивая согласованность интерфейсов с остальными модулями системы[cite: 1].

> ⚠️ **Важное правило защиты:** На зачётной неделе преподаватель опрашивает каждого участника **НЕ ПО СВОЕЙ РОЛИ** (например, Аналитика спрашивают по коду Разработчика или триггерам Администратора)[cite: 1]. Поэтому каждый участник обязан проводить вдумчивое Code Review чужих пул-реквестов.

### 🟣 Аналитик (@указать_ник)
- **Анализ предметной области и выбор датасета:**
  Исследование атрибутов выбранного датасета (1M+ строк), описание бизнес-процессов и нормализация схемы до 3НФ (минимум 8 связанных таблиц)[cite: 1].
- **Классификация и защита данных (152-ФЗ, 149-ФЗ):**
  Разделение атрибутов по категориям конфиденциальности: персональные данные (152-ФЗ), коммерческая тайна и открытые данные[cite: 1].
- **Закреплённые файлы и артефакты:**
  - `docs/analysis/data_map.md` — описание предметной области, выделение 8+ сущностей, карта данных и классификация[cite: 1];
  - `docs/analysis/access_matrix.md` — описание минимум 4 ролей, матрица доступа, требования к обезличиванию, шифрованию, журналированию и бэкапам[cite: 1];
  - `docs/diagrams/er_diagram.png` — физическая ER-диаграмма базы данных[cite: 1];
  - `sql/schema.sql` — DDL-скрипт создания таблиц, ограничений (`PK`, `FK`, `NOT NULL`, `UNIQUE`, `CHECK`) и базовых индексов[cite: 1];
  - `sql/queries.sql` — 6–8 аналитических запросов (с `CTE`, `JOIN`, `GROUP BY`, оконными функциями), обычное представление (`VIEW`) и витрина данных (`MATERIALIZED VIEW` с `REFRESH`)[cite: 1].

### 🟢 Администратор БД / DBA (@указать_ник)
- **Среда и развёртывание:**
  Запуск и сопровождение локального экземпляра PostgreSQL 16+ через Docker Desktop / DBeaver.
- **Серверная логика (PL/pgSQL):**
  Разработка функции расчёта уровня кредитного риска (`HIGH/MEDIUM/LOW`), бизнес-триггера `BEFORE INSERT OR UPDATE` (проверка лимита кредита $\le 50\%$ от выручки за прошлый год) и триггера аудита изменений в таблицу `audit_log` в формате JSON/JSONB[cite: 1].
- **Управление доступом (DCL):**
  Создание минимум 4 ролей (`credit_analyst`, `credit_operator`, `loan_committee`, `db_admin`), настройка привилегий (`GRANT/REVOKE`) с разделением ПДн и коммерческой тайны, демонстрация блокировки запрещённых операций[cite: 1].
- **Мониторинг и диагностика:**
  Подключение расширений (например, `pg_stat_statements`) и написание запросов статистики по ресурсоёмким запросам, индексам и использованию диска[cite: 1].
- **Закреплённые файлы и артефакты:**
  - `docs/analysis/data_flow.png` — схема потоков данных[cite: 1];
  - `sql/triggers_functions.sql` — функции, процедуры, триггеры и запросы системной статистики[cite: 1];
  - `sql/roles.sql` — DCL-скрипт создания ролей и раздачи прав[cite: 1].

### 🔵 Разработчик (@указать_ник)
- **Наполнение БД и генерация данных:**
  Подготовка и загрузка тестового набора данных объёмом от 1 000 000 строк в нормализованные таблицы PostgreSQL[cite: 1].
- **Интеграционный слой на Python:**
  Подключение через `psycopg` / `SQLAlchemy`, параметризованный `SELECT`, транзакции с обработкой исключений и откатом (`rollback`), выгрузка `MATERIALIZED VIEW` в `pandas` и CSV, batch-загрузка и реализация архитектурного паттерна работы с СУБД[cite: 1].
- **Контроль качества данных (Data Quality):**
  Автоматическая проверка количества строк, поиск пропусков (`NULL`) и дубликатов по ключевым полям[cite: 1].
- **Производительность и оптимизация:**
  Замеры `EXPLAIN (ANALYZE, BUFFERS)` для 5 ресурсоёмких запросов до и после создания индексов (минимум 3 индекса: B-tree, GIN или BRIN), применение партицирования/оптимизации запросов[cite: 1].
- **Закреплённые файлы и артефакты:**
  - `sql/seed.sql` — скрипт загрузки/генерации тестовых данных (1M+ строк)[cite: 1];
  - `python/db_access.py` — клиентский Python-модуль работы с БД[cite: 1];
  - `README.md` (и финальные индексы в `sql/schema.sql`) — описание проекта, сравнительная таблица и разбор статистики `EXPLAIN ANALYZE`[cite: 1].
